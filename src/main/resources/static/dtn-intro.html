    처음 사용한다면 · 무엇부터 보면 되나요?
    
          
    ① 목적 선택 → ② 데이터·엔진 선택 → ③ 흐름 재생 → ④ 비교할 결과 확인
    
          
    첫 번째 탭은 전송 지연을 GNSS 거리 오차로 바꿨을 때 계산기가 이를 어떻게 해석하는지 설명합니다. 두 번째 탭은 선택한 엔진 조합에서 데이터가 목적지까지 온전하게 도달하는지 설명합니다.
    
          
    실제 시험에서는 송신 화면에서 입력을 준비하고, 필요하면 ‘지연 반영 PVT’를 선택한 뒤 시험을 시작합니다. 송신측은 요청·접수 정보를, 수신측은 도착·복원·비교 정보를 확인합니다. 이 안내 화면의 선택은 실제 시험 설정에 반영되지 않습니다.
    
        
    
        
    지연이 큰데 위치는 왜 거의 같을까요? · 시각과 수식
    
          
    각 위성의 원래 의사거리는 서로 다릅니다. 다만 시험에서 더하는 거리 c × Δt는 모든 위성에 같습니다. 계산기는 위치와 수신기 시계오차를 함께 추정하므로, 이 공통 증가분을 주로 시계오차로 설명할 수 있습니다.
    
          
    원래 관측: Pᵢ ≈ 위성까지의 거리ᵢ + c × b
    변경 관측: P′ᵢ = Pᵢ + c × Δt
    기대 결과: b′ − b ≈ Δt · 잔차 (b′ − b) − Δt ≈ 0
    
          
    GNSS 관측 시간축 — t₀는 원본 관측 시각, Pᵢ는 원본 의사거리, c는 빛의 속도(299,792,458 m/s)입니다.
    
          
    원래 송신 시각 역산: t_txᵢ = t₀ − Pᵢ / c
    지연 반영 관측 시각: t₁ = t₀ + Δt
    재계산 의사거리: P′ᵢ = c × (t₁ − t_txᵢ) = Pᵢ + c × Δt
    
          
    PC 시험 시간축 — S는 시험 시작 접수 시각, R은 수신 본문 수신 완료 시각입니다. 수집 후 시작까지의 대기는 포함하지 않습니다.
    
          
    시험 지연: Δt = R − S
    시험 기준 가상 송신 시각: T*ᵢ = S − Pᵢ / c
    같은 결과: c × (R − T*ᵢ) = Pᵢ + c × Δt
    
          
    T*ᵢ는 시험 시작에 맞춘 설명용 가상 시각입니다. 실제 계산은 GNSS 시간축과 궤도정보를 유지합니다. PC의 UTC를 GNSS 관측 시각에 그대로 대입하거나, 지연 동안 위성이 실제로 이동한 상황을 재현하는 시험이 아닙니다.
    
          
    비교 항목확인할 의미
    
            
    관측 시각 차이주입한 Δt만큼 이동합니다.
    
            
    Clock Bias 증가량Δt와 얼마나 가까운지 확인합니다.
    
            
    Clock Bias 잔차증가량 − Δt가 얼마나 작은지 확인합니다.
    
            
    위치 차이공통 지연이 주로 시계오차로 설명되면 이상적으로 작습니다.
    
            
    속도 차이Doppler는 유지하지만 위치·위성 방향·수치 계산에 따라 작은 차이가 날 수 있습니다.
    
          
    
          
    현재 측정 결과만으로 자동 합격을 뜻하지는 않습니다. 판정 허용오차는 시험 목적에 맞게 정해야 합니다. 시계오차로 설명되지 않는 경우에도 위치가 반드시 크게 변하는 것은 아니며, 해 계산 실패나 잔차 증가 등이 나타날 수 있습니다.
    
        
    
        
    RAW · AFS Frame + Metadata · I/Q는 무엇이 다른가요?
    
          
    전송 데이터송신측에서 하는 일수신측에서 하는 일
    
            
    GNSS RAW원본 GNSS 관측·항법 데이터를 준비데이터를 읽고 PVT 계산에 사용
    
            
    AFS Frame + Metadata선택한 1 Epoch의 PVT 계산 정보를 AFS에 담고 보존용 정보를 Metadata로 동봉AFS를 해석해 관측·항법정보를 복원하고 PVT 계산
    
            
    I/Q Sample공통 AFS 프레임을 사용해 신호 샘플 생성파일 무결성 확인 후 신호 추적·복호를 통해 PVT 계산
    
          
    
          
    현재 I/Q 기본 생성 예시는 90초·12 MHz·I/Q 각 8 bit로 약 2.16 GB입니다. 파일 재생 배속은 처리 속도 옵션이며, GNSS 시간이나 DTN 전송 속도를 배수로 바꾸지 않습니다.
    
        
    
        
    AFS 6,000 bits 안에는 무엇이 들어가나요?
    
          
    물리 프레임의 고정 크기와 부호화 구조를 유지합니다. 아래는 이해를 위해 인터리빙을 풀어 나열한 구성입니다.
    
          
    
            
    동기 + SB168 + 52 bits
    
            
    SB22,400 bits
    
            
    SB31,740 bits
    
            
    SB41,740 bits
    
          
    구간내용
    
            
    SB1기존 프레임 식별 구조 유지 · BCH 부호화 후 52 bits
    
            
    SB2기존 항법정보 · 정보 1,176 + CRC 24 bits → 부호화 후 2,400 bits
    
            
    SB3LNIS 확장: PVT 계산에 필요한 GPS LNAV 보충정보 · 정보 846 + CRC 24 bits → 부호화 후 1,740 bits
    
            
    SB4LNIS 확장: 해당 위성의 원본 1 Epoch 의사거리·Doppler·C/N0·관측 시각·유효성 등 · 동일하게 1,740 bits
    
          
    
          
    SB3·SB4의 LNIS 확장 내용은 공식 표준 메시지 할당을 의미하지 않습니다. 원본 의사거리를 보관하고, 시험 지연에 따른 변환은 수신측에서 수행합니다. I/Q도 같은 AFS 구성기를 사용하지만 수신 PVT의 관측값은 신호 추적으로 얻습니다.
    
        
    
        
    결과를 해석하기 전에 알아둘 점
    
          
    시계 동기화: 두 PC의 시계 차이가 있으면 측정 지연에 섞입니다. Clock Bias 증가량이 주입값과 같아도 실제 통신 지연의 정확성을 증명하지는 않습니다.
    
          
    지연 측정 범위: 시작 접수부터 수신 본문 수신 완료까지이므로 준비·변환·대기·전달 시간을 포함할 수 있습니다. 순수 전송망 지연만의 측정은 아닙니다.
    
          
    상호운용: DTN/HDTN 조합을 바꾸는 것은 엔진 선택이며 BP 버전 변환을 의미하지 않습니다. BP 버전 외에도 TCPCL/LTP 등 전송 계층, 목적지 식별자, 경로, 수명, 보안 설정이 호환돼야 합니다.
    
          
    무결성과 계산: 데이터가 동일하게 도착한 것과 PVT 계산이 유효한 것은 별도 결과입니다. LNIS의 수신·검증 결과와 실제 라우터 동작 근거도 구분해 확인하세요.
    
        
    
        
    용어를 쉽게 이해하기
    
          
    GNSS RAW
    위치 계산 전의 위성별 관측값과 항법정보입니다.
    
          
    PVT
    Position·Velocity·Time. 위치·속도·시각 관련 해를 말합니다.
    
          
    Epoch
    같은 관측 시점의 여러 위성 측정값을 묶은 단위입니다.
    
          
    의사거리
    위성까지의 거리뿐 아니라 수신기 시계오차 등이 포함된 거리 관측값입니다.
    
          
    Doppler / C/N0
    각각 수신 주파수 변화 관측값과 신호 품질을 나타내는 지표입니다.
    
          
    Ephemeris
    위성의 위치와 시계 보정 계산에 필요한 궤도·시계 정보입니다.
    
          
    Clock Bias
    기준 시각에 대한 수신기 시계의 어긋남입니다. 계산기가 위치와 함께 추정합니다.
    
          
    DTN / HDTN
    이 화면에서 선택하는 송수신 엔진입니다. DTN은 ION 계열, HDTN은 NASA HDTN을 가리킵니다.
    
          
    Bundle / BP
    DTN이 전달하는 데이터 단위와 그 프로토콜입니다. 네트워크 상황에 따라 저장 후 전달할 수 있습니다.
    
          
    I/Q Sample
    신호의 두 성분을 시간순으로 저장한 디지털 샘플입니다.
    
          
    SHA-256
    파일 내용으로 계산하는 지문입니다. 송수신 파일 지문을 비교해 무결성을 확인합니다.
