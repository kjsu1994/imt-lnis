전송 데이터 변환 3단계 엔진 (1 Epoch 추출 → 의사거리 역산 시각 변환 → Solver 격리 패킷화)

지연 시험 전달 코덱(DelayTransferCodec.java) 및 지연 시간 변환기(DelayTime.java): 원본 GRAW 로그에서 지정된 1 Epoch 관측 레코드와 선행 항법 데이터를 추출하고, 의사거리를 펨토초 정밀도의 가상 송신 시각(transmitAt)으로 변환한 뒤, Reference를 완전 격리하여 전송 패킷을 구성하는 세부 처리 과정입니다.

1단계: 1 Epoch 관측 레코드 및 선행 항법 데이터 추출 (1 Epoch Selection) 단일 에포크 격리 · 선행 LNAV 보존
선택 추출: select(records, Epoch(week, tow)) → 1 ObservationEpoch + Preceding LNAV Messages 정규화 검사: epoch.week == selected.week && epoch.receiverTowSeconds == selected.towSeconds 시간축 보존: GrawCodec.decode(record) 바이트 및 헤더 구조 원형 유지
  • 단일 관측 에포크 엄격 제한: 다중 에포크가 섞이면 번들 네트워크 지연(Δt = R − S)이 에포크별로 다르게 작용하므로, 공통 지연 흡수(Clock Bias Absorption) 검증을 위해 정확히 1개 관측 에포크만 선별 분리
  • 선행 유효 궤도력(LNAV) 보존: 해당 에포크 관측 시점 이전에 수신된 위성별 유효 궤도 파라미터(Subframe 1~3, 30개 워드)를 그대로 유지하여 수신단 궤도 계산 준비
⚠️ 없으면 발생하는 문제: 여러 에포크가 혼입되면 위성별 시차가 어긋나 공통 지연 거리(c·Δt) 흡수 원리가 파괴되어 측위 오차가 발생함
2단계: 의사거리 → 가상 송신 시각(transmitAt) 펨토초 역산 (Delay Time Transformation) 거리 삭제 · 10⁻¹⁵초 역산 변환
가상 송신 시각: T*ᵢ = S − Pᵢ / c (S: 시험 시작 접수 시각, Pᵢ: 원본 의사거리, c = 299,792,458 m/s) 정밀도 분할: transmitAt = { "seconds": ⌊T*ᵢ⌋, "femtoseconds": (T*ᵢ − ⌊T*ᵢ⌋) × 10¹⁵ } 거리 필드 삭제: observation.remove("pseudorangeMeters") (원형 도플러·C/N0·상태 플래그는 보존)
  • 의사거리(Pᵢ) 사전 소거: 수신단이 원본 거리를 참조하지 못하도록 pseudorangeMeters 필드를 JSON에서 완전히 삭제
  • 펨토초(10⁻¹⁵s) 고정밀 역산: 시험 시작 접수 시각(S)에서 원본 전파 전파 시간(Pᵢ/c)을 감산하여 가상 송신 시각(T*ᵢ)을 생성하되, 부동소수점 오차를 방지하기 위해 초(seconds)와 펨토초(femtoseconds)로 분할 패킹
  • 관측 품질 지표 보존: 반송파 도플러 편이(dopplerHz), 신호 강도(carrierToNoiseDbHz), 추적 상태(trackingStatus)는 원본 그대로 보존하여 수신단 속도 산출 및 WLS 가중치 계산에 활용
⚠️ 없으면 발생하는 문제: 단정밀도 부동소수점 사용 시 수 밀리미터 이상의 환산 오차가 발생하므로 15자리 펨토초 분할 보존 필수
3단계: 원본 및 Reference 완전 격리 패킷 직렬화 (Strict Packet Isolation) 정답 사전 차단 · 사후 REST 대조
격리 삭제: packet.remove("referencePvt", "sourceSha256", "metadata", "file") 전송 스키마: GNSS_RAW · format: "LNIS-GRAW-DELAY-v2" · schemaVersion: 2 페이로드: { "testId": "...", "startedAt": "...", "records": [ { "observation": { "transmitAt": ... } } ] }
  • 수신단 솔버 정답 격리: 송신부 기준 위치/속도(Reference PVT) 및 원본 파일 해시를 전송 패킷에서 영구 제거하여, 수신단이 전달받은 시각 데이터만으로 순수하게 PVT를 산출하도록 강제
  • 사후 REST 대조 체계: 수신 PVT 계산이 완전히 종료된 이후에만 송수신 서비스 간 내부 REST API로 원본 RAW 및 Reference를 조회하여 전달 전후 일치 여부를 대조 검증
⚠️ 없으면 발생하는 문제: Reference가 수신부에 사전 노출되면 수신 솔버가 정답에 의존할 위험이 있어 지상 시험의 독립성과 신뢰성이 훼손됨

⚠️ 없으면 발생하는 문제: 잡음 없는 비현실적 신호가 생성되어 SDR 수신기의 동기 루프 및 신호대잡음비(C/N0) 추정기가 비정상 동작함

2비트 ADC: sample ≥ 0 ? (sample > thresh ? +3 : +1) : (sample < -thresh ? -3 : -1) 저장 포맷: INT8X2 (I, Q 성분을 각 1바이트 signed char로 교차 패킹) 파일 크기: 90초 × 12,000,000 samples/s × 2 (I, Q) = 2,160,000,000 bytes (정확히 약 2.16 GB)
  • 2비트 4단계 부호·크기 양자화: 최적 임계값(thresh)을 기준으로 아날로그 합성 샘플을 -3, -1, +1, +3의 4단계 정수로 양자화(Sign 1b + Magnitude 1b)
  • INT8X2 바이트 패킹: 2비트 양자화된 I와 Q를 각각 1바이트(signed int8)에 매핑하여 [I0, Q0, I1, Q1, ...] 순서로 공유 폴더에 BIN 파일로 기록
  • SB4 지연 에뮬레이션과의 차이: I/Q 모드는 90초 물리 전파를 직접 생성하므로 SB4에 가상 송신 시각(T*ᵢ)을 넣지 않고 정상 관측 레코드를 탑재함
⚠️ 없으면 발생하는 문제: 양자화 레벨이 어긋나면 신호 왜곡 및 가상 상관 피크가 발생하여 수신단 포착 실패로 이어짐

PocketSDR-AFS 5단계 신호 처리 엔진 (신호 포착 → 반송파/코드 추적 → AFS 복호 → Solver 격리)

C 네이티브 SDR 수신기(pocket_trk.c) 및 Java 프레임 복원기(IqFrameRecovery.java): 수신 공유 폴더의 2.16 GB BIN 파일에 대해 크기·해시 검증을 수행하고, FFT 고속 포착, 다중 루프 추적, AFS 프레임 복호, 그리고 엄격한 Reference 격리 원칙하에 독립적인 지구 PVT를 산출하는 세부 처리 과정입니다.

1단계: 수신 파일 무결성 및 SHA-256 검증 (File Integrity Check) 파일 크기 2.16 GB 대조 · SHA-256 1:1 검증
파일 크기: size(file.bin) == 2,160,000,000 bytes (정확히 90s × 12 MHz × 2B) 해시 검증: SHA-256(file.bin) == JSON.file.sha256 (단 1비트 불일치 시 SDR 구동 즉시 중단) 저장 격리: 수신 공유 폴더(/exchange)에 보관하며 DB 및 HTTP 바디 인입 금지
  • 엄격한 바이너리 무결성 확인: DTN을 통해 수신된 2.16 GB BIN 파일의 크기와 SHA-256 체크섬을 시험 JSON 메타데이터와 대조하여 전송 중 파일 손상 여부를 사전 차단
  • 불완전 파일 처리 방지: 파일이 없거나 크기/해시가 1바이트라도 일치하지 않으면 이후 SDR 추적 및 신호 처리를 일절 진행하지 않고 조기 거부
⚠️ 없으면 발생하는 문제: 전송 불완전으로 깨진 I/Q 파일이 SDR에 입력되어 무한 루프나 세그멘테이션 오류(Crash)를 유발함
2단계: FFT 기반 2차원 고속 신호 포착 (Parallel Code & Doppler Acquisition) 주파수/코드 2차원 탐색 · 상관 피크 검출
도플러 탐색 범위: f_D = −5,000 Hz ~ +5,000 Hz (탐색 빈 간격 250 Hz) 코드 위상 탐색: τ = 0 ~ 2,045 chips (순환 상관: R(τ, f_D) = IFFT[ FFT(Signal) × FFT*(Local_Code) ]) 피크 검출 판정: Peak-to-Average Ratio > V_thresh → 신호 획득 (Signal Lock)
  • FFT 기반 병렬 코드 위상 탐색: 입력 I/Q 신호와 수신기 내부 로컬 복제 코드(Gold/Weil)의 순환 상관을 FFT 및 IFFT로 일괄 고속 연산
  • 도플러 주파수 빈 순회: 위성 공전 속도(초속 약 3.9 km)로 인한 최대 ±5 kHz 도플러 편이를 250 Hz 간격으로 스캔하여 2차원 상관 평면에서 뚜렷한 피크 검출 시 신호 획득(Lock)
⚠️ 없으면 발생하는 문제: 도플러 주파수 오프셋을 찾지 못해 신호 에너지가 분산되어 수신기가 위성 신호를 전혀 획득하지 못함
3단계: 다중 루프 연속 추적 및 고속 파일 재생 제어 (PLL/DLL Tracking & 20x Replay) 반송파(PLL) · 코드(DLL) · 20배속 재생 동기화
반송파 루프: 3차 PLL / FLL → 도플러 편이(f_D) 및 반송파 위상 연속 추적 코드 루프: Early-Prompt-Late 3상관기 DLL → 코드 도달 시간(τ) 및 의사거리(P_i = c·τ) 추적 고속 재생: -tscale 20 (20배속) + iq_file_replay.h (채널 간 ≥100 ms 상관 여유 동기화)
  • 반송파 및 코드 위상 연속 추적: Costas PLL과 FLL로 반송파 위상 및 도플러를 추적하고, Early/Prompt/Late 상관기로 코드 칩 지연을 나노초 정밀도로 연속 추적
  • 20배속 고속 파일 재생 제어: `-tscale 20` 옵션으로 90초 분량 파일을 디스크에서 수 초 내로 고속 재생하며, `06-file-replay.patch`와 `iq_file_replay.h`가 가장 느린 채널 기준으로 최소 100 ms 여유를 보장하여 경합(Race Condition) 및 조기 종료를 원천 방지
  • 신호 물리 시간 불변: 20배속은 파일 디스크 읽기 속도일 뿐이며, 신호 내부의 샘플링 레이트(12 MHz), 관측 시각(TOW), 도플러 주파수를 일절 변경하지 않음
⚠️ 없으면 발생하는 문제: 고속 디스크 읽기 시 채널 간 처리 속도 차이로 인해 특정 위성이 조기 종료되어 유효 위성 수(4기 이상)가 부족해짐
4단계: 심볼 복조 및 AFS 프레임 복호 (Demodulation & Frame Extraction) Prompt 심볼 복조 · LDPC/CRC 통과 프레임 추출
심볼 복조: Prompt 상관기 2 ms 적분 → 6,000 BPSK 심볼 비트스트림 복조 AFS 복호: SP 68b 검출 → SB1 BCH(51,8)+MSB 복호 → 60×98 디인터리빙 → LDPC SF2/SF3 복호 → CRC-24 재계산 출력 스트림: $IQAFS,<sample time>,<PRN>,<block>,<packed hex> (CRC 무결성 통과 시에만 출력)
  • 2 ms 심볼 경계 동기화: Prompt 상관기 신호 적분으로 500 sps BPSK 심볼 경계를 확정하고 비트스트림 추출
  • 물리 계층 오류 정정 및 무결성 검증: 68비트 SP 동기 패턴 검출 후 SB1(FID 2b + TOI 7b, MSB 1b 직결 + BCH(51,8) 51b), 60행×98열 디인터리빙, LDPC SF2/SF3 Sum-Product 복호, NASA 표준 CRC-24 재계산 수행
  • $IQAFS 스트림 방출: LDPC 복호와 CRC-24 검증을 모두 통과한 서브블록(SB2, SB3, SB4)만 Java 상위 수신기로 방출 (오류 프레임 원천 차단)
⚠️ 없으면 발생하는 문제: CRC 검증이 누락되면 LDPC 오수렴으로 인한 잘못된 궤도 파라미터가 솔버에 인입되어 수십 km 측위 오차 발생
5단계: 관측값 집계 및 Solver 완전 격리 (Observable Gathering & Solver Isolation) RF 관측값 집계 · LNAV 720b 복원 · Reference 격리
관측값 집계: $IQOBS로부터 의사거리(P_i), 도플러(f_D), C/N0 집계 (최소 4기 이상 위성 연립) 궤도력 복원: IqFrameRecovery가 $IQAFS 블록 결합 → u-blox LNAV 720비트(30개 워드) 원형 복원 Solver 격리: Reference PVT 및 JSON 관측값은 SDR/RTKLIB 인입 원천 차단 → 순수 신호 복원 기반 독립 측위
  • RF 추적 관측값과 궤도력 결합: SDR이 신호에서 직접 추적한 의사거리·도플러와 `$IQAFS`에서 복원한 LNAV 720비트 궤도력을 결합하여 RTKLIB 기반 4단계 SPP PVT 솔버 구동
  • 엄격한 Solver 격리 원칙: 요청 JSON에 포함된 송신부 Reference PVT나 SB4 원본 관측값은 PocketSDR 추적기나 RTKLIB PVT 솔버의 입력으로 절대 전달되지 않으며, 오직 수신 PVT 계산이 끝난 후 비교 단계에서만 독립 대조용으로 사용됨
⚠️ 없으면 발생하는 문제: Reference가 솔버에 유입되면 실제 수신 신호 처리 성능을 검증하지 못하고 가짜 성공(False Positive)을 초래함

AFS 프레임 복원 5단계 무결성 엔진 (L1 물리 복호 → L2 데이터 무손실 재구성)

C 네이티브 코덱(lnis_afs_codec.c) 및 Java 프레임 처리기(AfsPvtFrameCodec.java) 파이프라인: 수신된 750바이트(6,000심볼) 프레임으로부터 동기 검출, 디인터리빙, 천공 역소거, LDPC 순환 복호, CRC-24 재계산, LNAV 720비트 무손실 복구 및 Canonical 검증을 수행하는 세부 복원 과정입니다.

1단계: 프레임 동기 부호(SP) 검출 및 SB1 BCH(51,8)+MSB 복호 나노초 동기 · 시간 간격 확정
SP 검출: Frame[0..67] == 0xCC 63 F7 45 36 F4 9E 04 A0 (Auto-correlation Peak) SB1 복호: BCH_Dec(Frame[68..119]) → FID = 0 (2 bits, 정규 항법 프레임), TOI = 0~99 (7 bits, 에포크 카운터)
  • 프레임 시작점 확정 (Frame Lock): 우주 전파 잡음 속에서 6,000심볼(750B) 프레임의 정확한 시작 경계를 나노초 단위로 검출 (불일치 시 AFS synchronization pattern mismatch 조기 거부)
  • BCH(51,8) 순환 부호 복호: 9비트 정보(FID 2b + TOI 7b) 중 최상위 1비트(MSB) 마스킹 해제 및 43비트 패리티 순환 오류 정정으로 12초 주기 내 시간 간격 카운터 TOI(0~99) 정합성 확인
⚠️ 없으면 발생하는 문제: 프레임 경계(Frame Boundary)를 찾지 못해 전체 6,000비트가 밀려 비트스트림 해독 자체가 불가능해짐
2단계: 60행 × 98열 블록 디인터리빙 (Block Deinterleaving) 연집 오류 분산 해제 · 서브블록 분리
입력 심볼: Interleaved Symbols (Bit 120 ~ 5999, 총 5,880 bits) 역변환 공식: deinterleaved[k++] = frame[j × 60 + i + 120] (i = 0..59 행, j = 0..97 열) 출력 분리: SB2 Coded (2,400b) + SB3 Coded (1,740b) + SB4 Coded (1,740b)
  • 우주 채널 연집 오류(Burst Error) 분산 해제: 송신 시 심각한 페이딩(Deep Fading)에 대비해 60행×98열 행렬(행 방향 기록, 열 방향 출력)로 흩뿌려진 5,880개 심볼을 역순회로 재정렬
  • 3대 서브블록 Coded Stream 분리: 통합 궤도·섭동·시계력(SB2, 2,400b), 알마낙·보충 슬롯 패딩(SB3, 1,740b), 시험 관측값(SB4, 1,740b)으로 분할
⚠️ 없으면 발생하는 문제: 채널 잡음으로 인한 연속 비트 파괴가 특정 서브블록에 집중되어 LDPC 오류 정정 한계를 초과함
3단계: 천공 역소거(Depuncturing) 및 LDPC 순환 복호 삭제 심볼 주입 · Sum-Product 순환 정정
SB2: [Erasure(240b)] + [SB2_Coded(2,400b)] + [Erasure(3,600b)] → sdr_decode_LDPC_SF2 → 1,200 bits SB3/4: [Erasure(176b)] + [Syms_A(694b)] + [Erasure(10b)] + [Syms_B(1,046b)] + [Erasure(2,650b)] → sdr_decode_LDPC_SF3 → 870 bits
  • 천공 삭제 심볼(Erasure) 역소거: 무선 대역폭 절약을 위해 전송 생략된 위치에 ERASURE(2) 심볼을 주입하여 LDPC 복호기 입력 버퍼(SF2: 6,240b, SF3: 4,576b) 구성
  • Sum-Product (Belief Propagation) 알고리즘: 희소 패리티 검사 행렬(H) 기반 확률 전파를 통해 무선 전송 중 반전된 오류 비트를 최대 수십 회 반복 연산으로 자동 정정
⚠️ 없으면 발생하는 문제: 무선 통신 과정에서 발생한 심볼 반전(오류)을 복구할 수 없어 비트 에러율(BER)이 급증함
4단계: NASA 표준 CRC-24 재계산 및 비트 무결성 검증 NASA 표준 CRC-24 1:1 대조 검증
재계산: CRC_calc = append_CRC24(Decoded_Data[Data_Len]) (g(x) = x²⁴ + x²³ + x¹⁸ + ... + 1) 비트 판정: memcmp(CRC_calc, Decoded_Data + Data_Len, 24 bits) == 0 검증 대상: SB2 (1,176b 데이터 + 24b CRC) / SB3 (846b + 24b) / SB4 (846b + 24b)
  • 수신단 독립 재계산 검증: 복호된 순수 정보 비트로부터 NASA AFS 표준 24비트 생성 다항식으로 CRC-24를 직접 재계산하여 전송받은 24비트 패리티와 1:1 비교 (crc_ok)
  • 1비트 무오류 엄격 판정: 단 1비트라도 불일치 시 복호 실패로 판정하여 오수렴된 프레임이 항법 계산으로 인입되는 것을 원천 차단
⚠️ 없으면 발생하는 문제: LDPC 복호기가 오수렴(False Convergence)했을 때 잘못된 궤도/시계 정보가 걸러지지 않고 PVT 엔진에 인입되어 수십 km의 측위 오차 발생
5단계: LNAV 720비트 무손실 궤도력 복원 및 Canonical 검증 SB2 통합 LNAV 복원 · Canonical 무관용 검증
LNAV 720b 복원: Word 1~10 (SF1~3) = [SB2 전반부 10개 핵심 요소 262b] ∪ [SB2 후반부 섭동·보충 459b] SB3 패딩 검증 & SB4 복원: SB3 0101 패딩 검증(846b), SB4 가상 송신 시각(T*ᵢ = S − Pᵢ/c)·Doppler·C/N0·Klobuchar·기준시(S) Canonical 검증: Arrays.equals(Re_Encoded(Payload), Received_SB234) == true
  • SB2 단일 블록 기반 LNAV 720비트 원형 복원: SB2 전반부의 10개 기본 케플러 요소(Bit 22~283, 262b)와 SB2 후반부의 6종 조화 섭동 계수/상태 플래그(Bit 342~800, 459b)를 역슬롯팅 결합하여 u-blox 30개 워드(720비트)를 1비트의 손실 없이 원형 복원하며, SB3(846b)는 표준 0101… 패딩 무결성을 검증
  • 관측값 및 가상 송신 시각 추출: SB4에서 DTN 지연 에뮬레이션용 가상 송신 시각(T*ᵢ)과 Doppler, C/N0, 전리층 보정 계수 복원
  • Canonical Re-encoding 무관용 검증: 복원된 데이터 객체를 가상 재인코딩하여 수신된 비트와 1:1 바이트 단위로 대조(Arrays.equals) 통과 시에만 PVT 엔진에 공급
⚠️ 없으면 발생하는 문제: 섭동 파라미터 유실 시 100m 궤도 오차가 발생하며, 가상 송신 시각 불일치 시 DTN 지연 에뮬레이션이 왜곡됨

2가지 시각(Time) 운용 체계: 실제 위성 송신 시각 vs 보정 송신 시각

시각 분리 운용 배경: 우주 공간에서 초속 약 3.9 km로 공전하는 위성의 실제 물리 궤도를 고정하고, 지상 소프트웨어 시험베드에서 DTN 네트워크 지연(Δt)을 의사거리에 정확히 주입하기 위해 2가지 시각 체계를 명확히 분리하여 사용합니다.

구분 항목 실제 위성 송신 시각
(t_txᵢ = t₀ − Pᵢ/c)		 지연 보정 송신 시각
(T*ᵢ = S − Pᵢ/c)
물리적 정의 전파가 실제 GPS 위성 안테나를 떠난 우주 물리적 발신 시각 (t₀: 관측 기준시, Pᵢ: 원본 의사거리) 시험 시작 접수 시각 S를 기준으로 원본 전파 전파 시간(Pᵢ/c)을 역산하여 생성한 지상 시험용 가상 송신 시각
주요 사용처 위성 3차원 궤도 좌표 (X^sᵢ, Y^sᵢ, Z^sᵢ) 및 위성 원자시계 오차(dt^sᵢ) 계산 수신단 의사거리 역산 및 DTN 통신 지연 에뮬레이션 주입 (P′ᵢ = c × (R − T*ᵢ))
역할 및 고정 필수 이유 위성 실제 우주 위치 고정 (필수):
GPS 위성은 초속 약 3.9 km로 고속 공전하며 지구 자전계(ECEF)도 함께 회전합니다. 전파가 위성을 떠난 실제 시각 기준으로 궤도를 전파해야만 우주 공간에서 위성 위치가 실제 관측 기하와 일치합니다.
(만약 네트워크 지연 Δt만큼 궤도 계산 시점까지 임의로 지연시키면 위성이 수십~수백 km 엉뚱한 위치로 이탈하여 측위 자체가 파괴됨) 		공통 지연 거리 주입 (에뮬레이션):
지상 수신 서버에는 무선 RF 안테나나 하드웨어 상관기(Correlator)가 없으므로, 번들 네트워크 도착 시각 R과 시험 시작 시각 S의 시차(Δt = R − S)를 모든 위성의 의사거리에 균일한 거리 지연(cΔt)으로 주입합니다.
(P′ᵢ = c(R − (S − Pᵢ/c)) = Pᵢ + c(R − S) = Pᵢ + cΔt)
PVT 솔버 결합 원리 공통 지연 흡수(Clock Bias Absorption)의 수학적 원리:
위성의 우주 위치 (X^sᵢ, Y^sᵢ, Z^sᵢ)는 '실제 위성 송신 시각'으로 원래 궤도에 정확히 고정해 두고, 의사거리 P′ᵢ에만 '지연 보정 송신 시각'을 통해 cΔt 지연을 인입시킵니다. 그 결과, PVT 솔버가 사용자 위치 (x, y, z)는 원래 위치 그대로 0.000 mm 오차 없이 보존하고, 지연 cΔt 전량을 수신기 시계오차(Clock Bias, c·dt_r)로 전량 흡수하게 됩니다.

PVT 계산 엔진 4단계 핵심 과정 및 방정식

RTKLIB SPP 솔버 파이프라인: 원본 궤도력과 지연 의사거리로부터 사용자 3차원 위치, 속도, 시계오차를 산출하는 세부 계산 과정입니다.

1단계: 케플러 궤도 전파 방정식 (Kepler Orbit Propagation) 위성 위치 · 시계 계산
M(t) = M₀ + (√(μ/A³) + Δn)(t − t_oe) E − e·sin(E) = M(t) (Newton-Raphson 반복법) (X^s, Y^s, Z^s) = R_z(Ω_k) · R_x(i_k) · (r_k·cos u_k, r_k·sin u_k, 0)ᵀ
  • 궤도 16요소 대입: SB2 단일 서브블록에 통합된 6대 기본 케플러 요소와 조화 섭동 6종(C_rs~C_is), 세차율(Ω̇, IDOT, Δn), 원자시계 보정계수(t_oc, a_f0~a_f2)를 대입하여 관측 시점(t)에서의 위성 3차원 ECEF 좌표 및 위성 시계오차(dt^s) 산출
  • 궤도력 시간 고정 필수: 초속 약 3.9 km로 공전하는 위성의 실제 우주 위치를 원래 송신 시각으로 고정 (시간 임의 변경 시 수십 km 이탈 방지)
⚠️ 없으면 발생하는 문제: 위성의 우주 3차원 위치를 알 수 없어 수신기와 위성 간 기하학적 거리 측정이 무용지물이 됨
2단계: 기본 관측 방정식 (Pseudorange Observation Equation) 위치 (x,y,z) · 시계오차 (dt_r) 측위
P′ᵢ = ρᵢ + c·(dt_r − dt^sᵢ) + Iᵢ + Tᵢ + εᵢ ρᵢ = √[(X^sᵢ − x)² + (Y^sᵢ − y)² + (Z^sᵢ − z)²] (i = 1, 2, ..., N ≥ 4)
  • 4개 미지수 연립방정식: 사용자 3차원 위치 (x, y, z)와 수신기 시계오차 dt_r(거리 단위 c·dt_r) 총 4개의 미지수를 결정하기 위해 최소 4기 이상의 가시 위성 연립방정식 구성 필수 (Gauss-Newton 반복 테일러 선형화 풀이)
  • 공통 지연 흡수 원리: 모든 위성에 동일한 지연 거리(c·Δt) 부과 시 기하학적 위치 (x, y, z)는 0.000 mm 보존되고, 지연 전량은 수신기 시계오차 dt_r로 전량 흡수 (dt_r′ = dt_r + Δt)
⚠️ 없으면 발생하는 문제: 수신기와 위성 간 거리를 해석할 수 없어 3차원 사용자 위치 측위 불가
3단계: 속도 관측 방정식 (Doppler Velocity Equation) 3차원 속도 (v_x, v_y, v_z) · 주파수 드리프트
f_D,ᵢ = −(f₀/c) · (v⃗^sᵢ − v⃗_r) · e⃗ᵢ + f₀·ḋt_r e⃗ᵢ = (X⃗^sᵢ − x⃗) / ρᵢ (시선 방향 단위벡터)
  • 3차원 속도 벡터 및 시계 드리프트 추정: 반송파 도플러 주파수 편이(f_D, u-blox RAWX 계측)와 위성 속도 벡터(v⃗^s)를 이용하여 수신기가 초당 몇 미터로 움직이는지 3차원 속도 벡터 v⃗_r = (v_x, v_y, v_z) 및 수신기 내부 발진기 주파수 편이율(Clock Drift ḋt_r) 동시 추정
⚠️ 없으면 발생하는 문제: 위치 미분치(Δx/Δt)에만 의존해야 하므로 위치 측정 잡음과 시간 양자화 오차가 증폭되어 속도 오차가 수 배 이상 급증함
4단계: 가중최소자승(WLS) 및 대기 오차 모델링 (WLS & Error Modeling) 가중치 W · Klobuchar 전리층 보정
Δx̂ = (Gᵀ W G)⁻¹ Gᵀ W Δy (W = diag(σᵢ⁻²)) P_corrected = P′ − I_klobuchar(α₀~α₃, β₀~β₃) − T_hopfield
  • WLS 가중최소자승: 신호 품질(C/N0)이 우수하고 고앙각(High Elevation)에 위치한 위성에 높은 가중치를 부여하여 저앙각 다중경로(Multipath) 신호의 오차 전파 억제
  • Klobuchar 전리층 모델 사전 감산: 태양 복사로 대기 상층부를 통과할 때 발생하는 수~수십 미터 전파 지연 오차(Iᵢ)를 항법 메시지 8대 파라미터(α₀~α₃, β₀~β₃)로 사전 감산 보정
⚠️ 없으면 발생하는 문제: 저품질 신호의 잡음 및 대기 지연 미보정으로 인해 수 미터에서 수십 미터 이상의 위치 오차 발생

2원화 평가 체계: 데이터 전달 무결성 vs 항법 PVT 지연 검증

평가 도메인 분리 원칙: 지상 시험베드에서 데이터 전달 무결성(네트워크 전송 무손실)과 항법 PVT 계산 결과(지연 흡수 및 기하학적 측위)는 서로 다른 독립적 평가 도메인입니다. 전달 데이터가 완전히 일치하더라도 위성 가시성이나 기하학적 배치(DOP)에 따라 PVT 해가 달라질 수 있고, 반대로 PVT 계산이 실패하더라도 전달 데이터 자체는 무손실일 수 있으므로 두 결과를 명확히 분리하여 확인합니다.

3단계 결과 비교 엔진 파이프라인 (3-Step Post-Comparison Pipeline)

수신부 비교 알고리즘: 수신 솔버의 독립적인 PVT 연산 완료 후, 송신 서비스와의 사후 REST 연동, 물리적 차이 산출, 그리고 2원화된 최종 상태 판정까지의 체계적인 3단계 처리 과정입니다.

1단계: 사후 REST 원본 조회 및 재생성 해시 대조 (Strict REST & Reproduce-and-Digest) 사전 정답 차단 · 수신 결과 영구 보존
REST 요청: GET /api/dtn/reference/{testId} (수신 PVT 계산 완료 후 비로소 호출) 재생성 엔진: DelayTransferCodec.prepare(jobId, rawRecords, isGnssRaw, startedAt, codec) 해시 대조: SHA-256(packet_recreated) == snapshot.payloadSha256
  • 사전 정답 오염 원천 차단: 수신 PVT 솔버가 연산 중에 원본 관측값이나 Reference PVT를 미리 참조하는 것을 원천 방지하기 위해, PVT 계산이 완전히 완료된 후에만 REST 엔드포인트로 비교자료(ReferenceSnapshot)를 호출
  • 재생성 해시 대조 (Reproduce & Digest): 송신단에서 의사거리를 보정 송신 시각으로 치환하고 Reference를 제외했으므로, 원본 파일과의 단순 바이트 대조는 불일치함. 따라서 원본에서 동일한 변환 엔진을 구동해 전달 데이터를 재생성한 후 해시를 대조하여 의도한 변환·제외를 손실로 보지 않고 무결성을 증명
  • 조회 지연 시 수신 결과 보존: 상대 노드의 REST 조회가 늦어지거나 네트워크가 일시 단절되더라도, 수신 노드가 이미 계산한 PVT 결과는 절대 폐기/롤백되지 않고 영구 보존되며 백그라운드 가상 스레드가 재조회를 지속
⚠️ 주의: 단순 원본 GRAW 바이트 비교 시 의도된 transmitAt 변환으로 인해 불일치로 오판할 수 있으므로, 반드시 동일 변환 엔진을 거친 재생성 패킷 해시로 대조해야 합니다.
2단계: 물리적 차이 산출 및 Clock Bias 잔차 방정식 (Physical Deltas & Clock Residual Equation) 지연 전량 시계 흡수 위치 0.000 mm 보존
위치 차이: d_pos = ||x_rx − x_ref|| = √[(ΔX)² + (ΔY)² + (ΔZ)²] [m] 속도 차이: d_vel = ||v_rx − v_ref|| = √[(ΔVx)² + (ΔVy)² + (ΔVz)²] [m/s] Clock Bias 변화: Δb = Bias_rx − Bias_ref [s] Clock Bias 잔차: εt = (수신 Bias − Reference Bias) − Δt = Δb − Δt [s] 거리 환산 잔차: εd = c × εt = 299,792,458 × [Δb − Δt] [m]
  • 차이 계산 기준: 모든 차이는 항상 수신 − Reference 기준입니다. 위치는 m, 속도는 m/s, Clock Bias는 s 단위로 계측합니다.
  • 공통 지연의 시계오차 흡수: 모든 가시위성에 동일한 지연 시간(Δt)이 인입되면, WLS 측위 행렬 풀이 시 기하학적 사용자 위치 (x, y, z)는 원래 위치 그대로 0.000 mm 오차 없이 보존되고 지연 전량이 수신기 시계오차(Clock Bias)로 전이됩니다 (Δb ≈ Δt ⟹ εt ≈ 0).
  • 위치 보존 ≠ 지연 부재: 위치 차이가 0.000 mm에 가깝다는 것은 지연이 발생하지 않았다는 뜻이 아니라, 지연이 위치 오차로 왜곡되지 않고 수신기 시계오차로 완벽히 격리·흡수되었다는 물리적 증거입니다.
  • 도플러 속도 차이 발생 원인: 동일한 수신 도플러 주파수(f_D)를 사용하더라도, 지연에 따라 계산된 위성 궤도 위치와 수신기 위치 간 시선 방향 단위벡터(e⃗ᵢ = (X⃗^sᵢ − x⃗) / ρᵢ)의 미세한 방향 차이에 의해 미세한 속도 편차가 발생할 수 있습니다.
💡 핵심 원리: Clock Bias 잔차(εt, εd)는 위치 오차가 아니며, 시계오차가 흡수한 시간과 주입한 지연의 물리적 차이를 진공 중 광속(c = 299,792,458 m/s)으로 환산한 관측치입니다 (허용오차 미설정).
3단계: 판정 상태의 본질과 물리적 해석 (Verdict Semantics: MEASURED vs INCONCLUSIVE) 측정 완료 (MEASURED) 독립 2원 평가
지연 PVT 판정: positionValid ? (velocityValid ? "MEASURED" : "PARTIAL") : "INCONCLUSIVE" 물리적 의미: MEASURED = 지연 반영 PVT 측정 완료 (허용오차 PASS/FAIL 판정이 아님) INCONCLUSIVE: 극심한 지연 또는 기하 배치 불량으로 인한 수렴 불가 (데이터 전달 무결성과 분리)
  • MEASURED의 본질 (측정 완료): MEASURED는 사전에 정의된 특정 오차 범위 이내로 들어와야 하는 합격(PASS) 판정이 아니며, 물리적 연산이 완료되어 측정값을 확보했음을 의미합니다.
  • 송수신 시계 차이 혼입: 실제 시험 환경에서는 독립된 송·수신기 발진기 시계 차이(Clock Drift)나 하드웨어 내부 군지연이 주입된 지연에 자연스럽게 섞이므로, 고정 임계치로 자르지 않고 관측치를 투명하게 보고합니다.
  • INCONCLUSIVE 판정 구분: 극심한 지연(수백 초 이상)이나 가시위성 부족으로 인해 연립방정식 해가 수렴하지 못하면 INCONCLUSIVE로 표기하며, 이는 데이터 전달 실패(MISMATCH)와 명확히 구분하여 확인합니다.
⚠️ 평가 분리: 큰 지연에서 PVT 해가 유효하지 않아 INCONCLUSIVE가 되더라도, 데이터 전달 일치 여부(COMPLETE)와는 별개의 독립적인 판정입니다.
